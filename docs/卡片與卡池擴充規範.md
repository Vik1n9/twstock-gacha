# 卡片與卡池擴充規範（beta 依據）

這份文件記錄 alpha 已定案的卡片視覺系統、特效分層與卡池擴充流程，作為 beta
新增板塊卡池、新增卡片型別、新增稀有度時的施工依據。模板檔在 `docs/templates/`。

---

## 1. 設計座標：兩條互不干擾的軸

卡片外觀由兩個**正交**的軸決定，新增任何東西前先確認它屬於哪一軸：

| 軸 | 值 | 決定什麼 | 真相來源 |
|---|---|---|---|
| **稀有度** | `C` / `R` / `SR` / `SSR` | 顏色、外框、框飾階級、翻牌爆點強度 | `lib/fx/core.ts` → `RARITY_COLOR` / `RARITY_FX` |
| **方向** | `UP` / `DOWN` | 卡體明暗（漲＝白卡、跌＝黑卡）、文字色 | `app/globals.css` → `.card-face.dir-UP` / `.dir-DOWN` |

**不要把兩軸混在一起**。例如「SSR 且跌」必須仍是黑卡＋橘框，而不是另開一種樣式。
新增第三軸（例如「限定卡」「聯名卡」）時，走**額外圖層**（多一個 `absolute inset-0`
的裝飾層），不要去改這兩軸既有的 token。

## 2. 卡片視覺規格

### 2.1 CSS 變數

稀有度 class（`.rar-C` / `.rar-R` / `.rar-SR` / `.rar-SSR`）提供：

| 變數 | 用途 | 備註 |
|---|---|---|
| `--rar` | 深底（黑卡）主色 | 同 `RARITY_COLOR` |
| `--rar2` | 漸層第二色 | 頂條、寶石 |
| `--rar-ink` | 淺底（白卡）用的加深版本 | 白卡上所有稀有度色都改用它，確保對比 |
| `--rar-glow` | 外光暈 rgba | 卡面 box-shadow |

方向 class 提供：

| 變數 | `.dir-UP`（白卡） | `.dir-DOWN`（黑卡） |
|---|---|---|
| `--rar-use` | `var(--rar-ink)` | `var(--rar)` |
| `--card-ink` | `#0f131b` | `#e8ecf4` |
| `--card-dim` | `#5f6a7d` | `#7d879a` |
| `--card-line` | `var(--rar-ink)` | `color-mix(var(--rar) 80%, #000)` |
| `--frame-inner` | `rgba(255,255,255,.85)` | `rgba(0,0,0,.92)` |
| `--up-c` / `--down-c` | `#c62828` / `#0f766e` | `#ff5252` / `#26a69a` |

**卡面內的所有顏色一律走 `--rar-use` / `--card-ink` / `--card-dim` / `--up-c` /
`--down-c`**，不要直接寫 `var(--rar)` 或 `var(--up)`，否則白卡會失去對比。

### 2.2 邊框階級

稀有度差異靠三層堆疊呈現，階級越高層數越多：

| 稀有度 | 主框 2px | 內襯線 1px | 四角框飾 | 外環 outline |
|---|---|---|---|---|
| C | ✓ | ✓ | — | — |
| R | ✓ | ✓ | — | 1px / offset 2px / 26% |
| SR | ✓ | ✓ | ✓ | 1.5px / offset 3px / 45% |
| SSR | ✓ | ✓ | ✓ | 2px / offset 4px / 62% ＋ 旋轉 conic 描邊 |

實作位置：`.rar-frame`（內襯線＋四角框飾，由 `StockCardFace` 渲染一個
`absolute inset-0` 的空 div）、`.rar-XX.card-face` 的 `outline`、
`.rar-SSR.card-holo::before`（conic 動畫）。

新增稀有度時**照這張表往上或往下加一級**，不要跳級或另創形式。

### 2.3 尺寸級距（variant）

卡框縮小時字級與欄位必須同步縮，否則文字會被 `overflow-hidden` 裁掉。

| variant | 卡框 | 使用場景 | 保留欄位 |
|---|---|---|---|
| `full` | ≥ 200px | 單抽大卡、放大檢視 | 全部（含階級名、收盤／昨日、板塊）；股名可換行 |
| `compact` | 130–200px | 十連結果格、抽卡紀錄格 | 去掉階級名；股名 truncate |
| `mini` | < 132px | 十連演出中的翻牌 | 徽章與 30 日漲跌拆兩列，去掉收盤／昨日／板塊 |

`FlipCard` 依 `size` 自動選 variant（`size < 132 → mini`，`< 200 → compact`）。
新增級距時同步改 `V` 常數表（`components/cards/StockCard.tsx`）與 `FlipCard` 的判斷。

**硬性規則**：任何卡面文字都要有 `truncate`（或 `full` 的 `break-words`）＋
父層 `min-w-0`，且不得出現固定 px 的字級。

## 4. 新增板塊卡池 checklist

alpha 只啟用 SEMI，且 `scripts/seed.ts` 把 SEMI 寫死了。beta 開新板塊要動這些地方：

1. **`lib/sectors/defs.ts`** — 該板塊 `active: true`，並把 `theme` 從 `placeholder`
   展開成完整定義（見 §5 與 `docs/templates/board-template.ts`）。
2. **`lib/sectors/industry-map.ts`** — 確認 TWSE 產業別代碼對應。標「未驗證」的代碼
   **必須先用實際個股驗證**（撈 `t187ap03_L` 找 2–3 檔已知個股比對），驗證後補 ✓。
3. **`scripts/seed.ts`** — 目前三處寫死 SEMI，要改成迴圈跑所有 `active` 板塊：
   - `fetchAndFilterSemi()` → 改成依 `boardCode` 分組
   - 只插入 `POOL_SEMI` 的區塊 → 改成 `BOARD_DEFS.filter(b => b.active)` 迴圈，
     `poolId` 用 `poolIdFor(tagId)`、`poolName` 用 `${tagName}池`
   - 「曾屬 SEMI 但已不在清單者停用」→ 改成逐板塊比對
4. **跑資料**：`npm run seed` → `npm run backfill` → `npm run snapshot`
5. **卡池開放門檻**：`lib/pool/snapshot.ts` 的 `gatePool()`，預設
   `minStockCount = 30`；冷門板塊不足 30 檔會被關閉，需在 `pools.min_stock_count`
   個別調整而不是改全域預設。
6. `/pools`、`/odds`、首頁卡池選擇會自動帶出，不需另外改。

## 5. 板塊主題 SectorTheme

`lib/sectors/defs.ts` 的 `SectorTheme` 是**特效系統的 config**。目前實作狀態：

| 欄位 | 型別 | alpha 是否已接 | 消費者 |
|---|---|---|---|
| `primary` | hex | ✅ | `SectorBackdrop` 星雲／隧道／粒子、`PreRoll` 板塊名、`CardBack` 底色 |
| `accent` | hex | ✅ | 徽章、節點、神光束、卡背切角與條碼 |
| `bg` | hex | ✅ | 演出層底色 |
| `particleShape` | enum | ⛔ 預留 | 目前一律畫方塊晶粒（`SectorBackdrop.drawChips`） |
| `motif` | string | ⛔ 預留 | 目前一律 `circuit` 透視隧道（`SectorBackdrop.drawTunnel`） |
| `tenLayout` | enum | ⛔ 預留 | 目前一律 `wafer_grid`（`WaferGrid` 的 `RING` 常數） |
| `ssrSignature` | enum | ⛔ 預留 | 目前一律 `WaferBurst` |

**beta 要補的分派點**（把 `⛔` 變 `✅` 的四個切換點）：

- `particleShape` → `SectorBackdrop` 的 `drawChips()`：抽成
  `SHAPE_RENDERERS[shape](ctx, x, y, size, color)` 查表。
- `motif` → `SectorBackdrop` 的 `drawTunnel()`：抽成
  `MOTIF_RENDERERS[motif](ctx, cam, t, boost)`；每個 motif 各自畫自己的世界
  （waves 用正弦帶、dna 用雙螺旋、skyline 用大樓剪影）。
- `tenLayout` → `WaferGrid` 的 `RING`／`positions`：抽成
  `LAYOUTS[tenLayout]: () => {x,y}[]`，長度固定 10。
- `ssrSignature` → `GachaStage` 的 `<WaferBurst />`：改成
  `SIGNATURES[theme.ssrSignature]` 查表取元件，介面統一為
  `{ theme, low, onDone }`（骨架見 `docs/templates/SsrSignatureTemplate.tsx`）。

新增板塊主題時，**先只填 `primary`/`accent`/`bg` 就能上線**（其餘欄位吃預設），
不需要等特效分派完成。

## 6. 特效分層架構

| 檔案 | 職責 | 擴充點 |
|---|---|---|
| `lib/fx/core.ts` | 相機投影、緩動、亂數、稀有度參數表 | 新增緩動／稀有度參數 |
| `components/gacha/SectorBackdrop.tsx` | 背景深度場（星雲／隧道／粒子／神光／bloom／噪點） | `motif`、`particleShape` 查表 |
| `components/gacha/PreRoll.tsx` | 前置演出（快門／徽章／板塊名／滾筒／蓄力／白閃） | 板塊專屬開場、稀有度預告規則 |
| `components/gacha/FlipCard.tsx` | 單張 3D 翻牌與落定，翻開時回呼座標 | 卡背造型、翻牌節奏 |
| `components/gacha/RevealFx.tsx` | 全畫面共用爆點層（環／碎片／火星／光柱／金塵／光斑／震動） | 新增粒子型別、依稀有度加階 |
| `components/gacha/WaferGrid.tsx` | 十連 3D 排列與翻牌排程（最高稀有度壓軸） | `tenLayout` 查表 |
| `components/gacha/WaferBurst.tsx` | SSR 簽名特效 | 依 `ssrSignature` 換元件 |
| `components/gacha/Resonance.tsx` | 板塊共振（同方向 5+／8+） | 共振規則、板塊專屬共振 |

**演出流程**：`GachaStage` 是唯一的狀態機（`idle → preroll → reveal → summary`），
`boost`（0–1）是背景強度的單一調節旋鈕，`hint`（最高稀有度）驅動彩光預告。
新增演出階段時加在這個狀態機上，不要在子元件裡自己控流程。

## 7. 效能與可及性守則（新元件一律遵守）

1. **`low` 分支必須有**：`useLowFx()` 為 true 時直接跳到終態，不跑 rAF、不掛事件。
2. **rAF 一定要清**：`useEffect` 回傳 `cancelAnimationFrame` ＋ 移除 listener；
   gsap 用 `tl.kill()` 或 `gsap.context().revert()`。
3. **粒子數依畫面面積推算**，不要寫死；上限要 clamp（參考 `SectorBackdrop` 的
   `clampNum(area / 5200, 90, 340)`）。
4. **`prefers-reduced-motion`**：CSS 動畫要在 media query 內關掉。
5. **canvas 用 `fitCanvas()`** 處理 devicePixelRatio，並在 resize 時重建。
6. **卡片文字**：見 §2.3 硬性規則。
7. **可點卡片**用 `.card-btn` class（hover 浮起、focus-visible 有 ring），
   並給 `aria-label`。

## 8. 抽卡紀錄資料結構

alpha 無帳號系統，紀錄存在瀏覽器 `localStorage`（key `twstock-history`，上限 600 筆）。
DB 的 `draw_records` 是**全站機率驗證用、不分玩家**，不要拿來當個人紀錄來源。

```ts
interface HistoryEntry extends DrawCard {
  id: string;            // `${drawnAt}-${index}-${stockCode}`
  drawnAt: number;       // epoch ms
  poolId: string;
  poolName: string;
  boardName: string | null;
  snapshotDate: string;
  drawType: "single" | "ten";
}
```

**beta 導入帳號時的遷移路徑**：在 `drawRecords` 加 `playerId`，寫入 API 時一併記錄；
`lib/history/store.ts` 的 `useHistory()` 改成先讀 API、失敗再退回 localStorage，
並提供一次性「把本機紀錄上傳到帳號」的合併流程（以 `id` 去重）。
`CardDetail` 與 `/history` 只吃 `HistoryEntry` 形狀，資料源替換不需要動 UI。
